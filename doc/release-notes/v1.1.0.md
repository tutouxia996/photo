# sq-fast v1.1.0 版本更新说明

- **发布日期：** 2026-06-15
- **关联平台依赖包：** sq-dependencies-core 1.1.0（同步发布）
- **变更编号：** [`platform-gm-upgrade`](../../openspec/changes/platform-gm-upgrade/)
- **兼容性：** **不向下兼容**（密码体系、JWT 算法、前端加密协议均发生破坏性变更，详见「升级影响」与「升级步骤」）

## 一、本次版本内容

1. **平台依赖包统一治理**：消除 sq-fast 与 sq-dependencies-core 之间的依赖重复声明、硬编码版本与误用变量，建立单一权威版本来源。
2. **国密合规改造**：登录链路全链路替换为 SM2 / SM3 国密算法，建立可复用的国密能力底座（`Sm2Utils` / `Sm3Utils` / `Sm4Utils`）。
3. **安全基线强化**：SM2 私钥统一通过 PKCS12 keystore 管理，密码通过环境变量注入，禁止任何形式的硬编码密钥。
4. **平台底座下沉**：将通用工具与基类下沉至 sq-common，sq-fast 不再持有平台级代码，提升复用度与边界清晰度。
5. **安全加固**：移除已知 CVE 高发的过时依赖（jjwt、springfox），收敛攻击面。
6. **升级账号安全策略**：首次登录、密码重置、长期未更新密码场景登录时，将强制跳转修改密码；新密码需符合系统复杂度规则方可保存。。

## 五、国密改造

### 4.1 密码编码：BCrypt → SM3

- 新增 `com.sq.common.crypto.Sm3PasswordEncoder`（实现 Spring Security `PasswordEncoder`）。
- 编码格式：`{sm3}<base64(salt)>$<hex(SM3(salt || rawPassword))>`，salt 16 字节，由 `SecureRandom` 生成。
- **不兼容旧 BCrypt 密码**：`matches()` 仅识别 `{sm3}` 前缀，对 `$2a$` / `$2b$` / `$2y$` 等 BCrypt 前缀直接返回 false。
- **上线必须执行批量重置 SQL**，将所有用户密码重置为 `{sm3}` 格式临时密码，并强制首次登录改密。

### 4.2 JWT 算法：HS512 → SM3-HMAC

- 完全弃用 jjwt，由平台自实现 JWT 三段编解码：

  ```text
  base64url(header) + "." + base64url(payload) + "." + base64url(SM3-HMAC(secret, header + "." + payload))
  ```

- JWT header `alg` 字段固定为 `SM3-HMAC`，`TokenService` 校验时拒绝其他算法。
- 签名密钥通过 `${SQ_JWT_SECRET}` 环境变量注入，不再使用代码默认值用于生产。

### 4.3 前端密码字段：RSA → SM2

- 前端登录页改用 `sm-crypto@0.3.13`，`cipherMode=1`（C1C3C2 模式，符合国标 GM/T 0003.4-2012）。
- **移除前端硬编码公钥**：登录前先调用 `GET /system/publicKey` 拉取后端 SM2 公钥（PEM 格式）。
- sq-ui (Vue2) 与 sq-ui-vue3 (Vue3) 双前端同步改造，移除 jsencrypt 依赖。

### 4.4 SM2 密钥管理

- 私钥统一存储为 PKCS12 keystore（`.p12`，BC Provider 加载）。
- 加载顺序：**外部路径优先 > classpath**。配置如下：

  ```yaml
  sq:
    crypto:
      sm2:
        keystore-path: classpath:keystore/sq-sm2.p12
        keystore-external-path: ${SQ_KEYSTORE_EXTERNAL_PATH:}
        keystore-password: ${SQ_KEYSTORE_PWD:changeit}
        key-alias: sq-sm2-key
        key-password: ${SQ_KEY_PWD:changeit}
        keystore-type: PKCS12
  ```

- 外部路径加载失败时**启动失败并记录明确错误日志**，禁止静默 fallback 到 classpath（避免运维误以为部署成功）。
- 提供 `Sm2KeystoreGenerator` 命令行工具用于生成 PKCS12 密钥对。

### 4.5 新增公钥接口

- `GET /system/publicKey`：permitAll，返回 PEM 格式 SM2 公钥。

## 八、升级影响

### 7.1 对所有现有用户

- **强制改密**：上线后所有用户原 BCrypt 密码失效，需通过临时密码 + 首次登录改密流程恢复访问。
- **强制修改密码流程**：用户首次登录或被重置密码后需先完成密码修改，前端在改密完成前限制进入业务页面，后端对强制改密状态进行校验。

### 7.2 对部署方与运维

- **必须配置三个新增环境变量**（生产环境强制要求）：

  | 环境变量 | 用途 |
  | --- | --- |
  | `SQ_KEYSTORE_PWD` | PKCS12 keystore 文件密码 |
  | `SQ_KEY_PWD` | SM2 key 条目密码 |
  | `SQ_JWT_SECRET` | JWT SM3-HMAC 签名密钥（≥ 32 字节强随机） |

- **可选环境变量**：`SQ_KEYSTORE_EXTERNAL_PATH`（指定外部 keystore 文件绝对路径，建议生产使用）。
- 生产环境 `.p12` 文件 chmod 600，与 jar 解耦部署。
- 仓库与镜像中 **禁止** 包含生产 keystore 文件与密码。

### 7.3 对前端开发与构建

- 前端依赖变化：`jsencrypt` 已移除，新增 `sm-crypto: 0.3.13`。
- sq-ui 与 sq-ui-vue3 均需重新执行 `npm install` 拉取新依赖。

### 7.4 对业务开发

- 引用 `TreeEntity` / `SecurityUtils` 等 7 个类时，import 路径**保持不变**（仍为 `com.sq.common.*`），无需调整。
- 自定义 `LoginUser` 子类需 `implements ILoginUser` 并实现三个方法。
- 直接调用 BC 或 Hutool 加密 API 的代码请改为通过 `Sm2Utils` / `Sm3Utils` / `Sm4Utils` 统一入口。

## 九、升级步骤（生产部署）

> **顺序强约束**：先后端 → 再前端，禁止颠倒。建议安排在低峰期窗口执行。

### 前置
1. 向所有用户发布密码重置通知与首次登录改密引导。
2. 在 staging 环境完整跑通登录闭环（拉公钥 → SM2 加密 → 后端解密 → SM3 校验 → SM3-HMAC JWT 签发 → 受保护接口验签）。
3. 三种数据库（MySQL / 达梦 / GaussDB）逐一执行新版 init.sql 与登录冒烟。
4准备生产 keystore 文件，分发至各应用节点 `${SQ_KEYSTORE_EXTERNAL_PATH}`，chmod 600。

### 部署
1. **数据库**：执行 `doc/db/reset_passwords_sm3.sql` 批量重置脚本（自动备份原 BCrypt 字段至 `backup_pwd_<timestamp>` 表）。
2. **后端**：部署 sq-admin-server 1.1.0，注入三个环境变量，启动后访问 `GET /system/publicKey` 验证返回 PEM。
3. **前端**：部署 sq-ui / sq-ui-vue3 新构建产物。
4. **冒烟**：用 admin / `Sq@admin2025`（或重置后的临时密码）登录，断言：
   - 请求 payload 中 password 字段为 SM2 密文；
   - 响应 JWT header `alg=SM3-HMAC`；
   - 携带新 JWT 调用受保护接口成功；
   - 旧 BCrypt 密码登录被拒绝。
